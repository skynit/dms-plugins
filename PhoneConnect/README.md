# 连接

DankMaterialShell（DMS）的手机与电脑连接插件。弹窗顶部切换“手机 / 电脑”：电脑页使用 FreeRDP 3 打开 Windows RDP 远程桌面；手机页在状态栏打开连接弹窗，扫描或手填手机地址，输入配对码，使用 scrcpy 在 Wayland 上投屏，把本机文件推送到手机，也能浏览手机目录并把手机文件下载到电脑。成功连接后自动记住一个设备的连接地址，之后一键重连。

状态栏显示设备图标，颜色仍表示手机的 ADB 状态（不表示 RDP 登录状态）：未连接时使用主题前景色（浅色主题为黑色），ADB 确认有已授权手机连接时显示绿色。颜色每 10 秒刷新一次，连接操作完成后也会立即刷新；图标的可访问名称会读出连接状态。保存过设备但已断线时不会显示绿色。

## 安装

运行时需要 DMS、`adb`、`scrcpy`、`avahi-browse`，并保持系统的 `avahi-daemon` 服务运行。Avahi 是 Linux 的局域网服务发现程序，负责查询手机发布的当前地址和端口；ADB 负责配对与调试连接，scrcpy 负责投屏。插件通过参数数组调用这些程序，不需要 Python，也不依赖系统 ADB 的 `mdns services` 命令。

CachyOS/Arch 的 `avahi` 包提供 `avahi-browse`。可用 `systemctl is-active avahi-daemon` 检查服务；未启动时由用户执行 `sudo systemctl enable --now avahi-daemon`。构建辅助程序时需要 Go，从本目录安装：

```bash
plugin_dir="${XDG_CONFIG_HOME:-$HOME/.config}/DankMaterialShell/plugins/PhoneConnect"
mkdir -p "$plugin_dir"
cp -a plugin.json PhoneConnect.qml PhonePopout.qml PhoneOptions.qml PhoneSource.qml ComputerConnect.qml ComputerSource.qml "$plugin_dir/"
GOAMD64=v1 CGO_ENABLED=0 go build -o "$plugin_dir/phone-connect" .
dms ipc call plugin-scan scan
dms ipc call plugins enable phoneConnect
```

在 DMS 设置的状态栏组件中添加“连接”。内部 ID `phoneConnect` 与安装目录保留，以兼容已有状态栏位置、手机设备和投屏选项。源码和安装目录是独立副本；更新时重复复制文件，执行 `dms ipc call plugin-scan rescan phoneConnect`。如果仍显示旧界面，稍后重启 DMS。

## 电脑远程桌面

电脑连接额外需要 `xfreerdp3`（CachyOS/Arch 的 `freerdp` 包），缺少时会提示安装，不影响手机功能。密码自动保存使用 `secret-tool`（`libsecret` 包）和 Secret Service 密钥环，例如已解锁的 GNOME Keyring。

1. 在目标 Windows 电脑开启远程桌面，确保网络可达且账号有远程登录权限。
2. 打开插件，切到“电脑”，填写 IP 或主机名、端口（默认 3389）、用户名、域或电脑名（选填）及密码。
3. 显示缩放可选 100%、140%、180%，默认 180%；动态分辨率默认开启。可选择忽略服务器证书验证和记录 DEBUG 日志。
4. 点击“连接电脑”启动独立的 FreeRDP 窗口；关闭插件弹窗不会关闭远程桌面。停止或重启 DMS 系统服务可能会同时结束远程桌面进程。界面显示的是客户端启动结果，实际认证及断线情况以远程桌面窗口和日志为准。

“保存设置”和“连接电脑”都会记住地址、账号及显示选项，并将非空密码自动存入系统密钥环。打开电脑页或编辑完地址、端口、账号、域后，自动读取匹配的密码并回填；不同电脑和账号的密码独立保存。点击“忘记密码”删除当前账号的记录。切走电脑页后清空输入框，下次进入重新读取密钥环。密钥环不可用时会明确提示；密码保存失败不阻止本次 RDP 启动，也不会回退为明文保存。

密码不写入插件设置，保存时通过标准输入传给 `secret-tool`。完整 RDP 参数通过 `xfreerdp3 /args-from:stdin` 的标准输入传递，不放到进程命令行；不调用 shell。字段中的换行和 NUL 会被拒绝。当前地址支持 IPv4 和主机名。

仅在信任目标电脑及网络时开启“忽略服务器证书验证”，它对应 `/cert:ignore`。日志位于 `${XDG_STATE_HOME:-~/.local/state}/dms-phone-connect/rdp.log`，每次启动覆盖，权限为 0600；DEBUG 日志用于排查连接问题。远程桌面窗口可用 Ctrl+Alt+Enter 切换全屏。

## 手机连接

手机和电脑连接同一局域网，在安卓开发者选项中打开「无线调试」。

1. 首次配对：打开「使用配对码配对设备」，保持页面显示。弹窗中点击扫描，只有一台候选手机时输入当前 6 位配对码即可；多个候选时先点选目标设备。提交时会再次查询所选 IP 的配对端口，只有一个候选时采用当前端口；多个候选必须与所填端口匹配，否则要求重新选择。也可填写配对页的 IP，**配对端口选填**；发现不可用时可手填完整配对地址。端口拒绝连接后只重新发现一次，仅在同一 IP 出现唯一的新端口时重试；配对码错误不会自动重试。
2. 配对成功后先检查同一 IP 是否已有唯一的在线 ADB 连接，有则直接投屏；否则寻找同一 IP 的**连接端口**并连接。未找到连接端口、Avahi 查询失败或连接失败时，会保留“配对成功”的事实、清空已使用的配对码，并提示填写无线调试主页的连接地址，无需再次配对。ADB 已连接但 scrcpy 启动失败会单独说明投屏故障。
3. 已配对手机也可直接扫描选择连接地址，或填写无线调试主页的 IP，**连接端口选填**；局域网发现不到端口时必须填写。连接成功会自动记住这台设备；如果打开弹窗时已有且仅有一台可确认的无线 ADB 手机，也会自动更新保存的设备地址。
4. ADB（Android 调试桥，由电脑上的 `adb` 程序与手机建立调试连接）已经连接手机时，弹窗会明确显示“ADB 已连接”，按钮显示“投屏”。点击后复用现有连接启动 scrcpy，不再连接保存的旧 IP，也不要求扫描成功；这与 `SDL_VIDEODRIVER=wayland scrcpy` 使用现有连接的方式一致，同时保留插件的投屏选项。多台手机在线时优先匹配保存的 ADB 设备标识或连接地址；无法确定目标时会要求直接选择设备或断开其他手机。

配对端口与连接端口不同。没有可复用的 ADB 连接时，一键连接先扫描：优先按保存的 ADB 设备标识查找当前地址，再按原 IP 查找新的连接端口；没有扫描结果时才尝试保存的地址。ADB 设备标识是调试工具识别连接目标时使用的名称，与 IP 和端口分开保存；无线服务名称变化且 IP 也变化时，需要重新扫描选择。扫描使用 Avahi 查询 mDNS（局域网设备用来发布、发现当前服务地址的机制）服务，依赖网络允许相关组播，不保证所有网络都能发现手机。Avahi 不可用、查询超时或解析失败会显示原因，空结果会提示打开无线调试；部分服务查询失败时仍保留另一类已发现的设备。Avahi 只能改善地址发现，不能修复 Wi-Fi 断线或手机关闭无线调试。插件不会替你打开手机的无线调试开关。

## 投屏选项

连接弹窗右上角的调节图标在**当前弹窗内**切换到投屏选项；返回按钮回到连接页面，不打开 DMS 系统设置。选项由 DMS 持久保存，并用于配对连接、直接连接及一键重连。默认全部关闭，音频使用 scrcpy 默认模式，录制不限时。

| 类别 | 设置 | 启动参数 |
| --- | --- | --- |
| 屏幕与唤醒 | 关闭手机实体屏幕 | `-S`，电脑仍继续投屏 |
| 屏幕与唤醒 | 接电时保持唤醒 | `-w`，退出 scrcpy 后恢复 |
| 屏幕与唤醒 | 持续模拟用户活动 | `--keep-active` |
| 屏幕与唤醒 | 启动时不主动点亮屏幕 | `--no-power-on` |
| 声音 | 手机与电脑同时播放 | `--audio-source=playback --audio-dup`，需要 Android 13 或更高版本；个别应用可以拒绝捕获 |
| 声音 | 不传输声音 | `--no-audio`，与同时播放互斥 |
| 录制 | 连接时录制 | `--record=~/Videos/phone.mp4`，可改 `.mp4` 或 `.mkv` 文件名；同名文件按序号避让 |
| 录制 | 录制时长上限 | 可选 `--time-limit=600`、`1800` 或 `3600`；计时结束投屏也会停止，仅启用录制时生效 |
| 输入 | 将电脑键盘作为实体键盘 | `-K`，手机可能需要配置实体键盘布局 |

只允许填写文件名，不接受目录或绝对路径；实际保存地址会在启动成功时显示。录制开启时，会在 `~/Videos` 下创建目录。仅添加当前选择的参数，不执行 shell 命令。

## 文件推送

连接弹窗底部的“文件推送”可以把本机文件推送到手机的 `/sdcard/Download/`。三种入口等效：

- **直接把文件拖到弹窗里**，或拖到状态栏的手机图标上，松开后立即开始推送（支持一次拖入多个文件）。
- 点“选择”打开文件选择器，可多选。
- 在输入框填写本机绝对路径后按 Enter，再点“推送到手机”。

- 传输期间状态栏的手机图标会变成百分比；ADB 还没报告具体进度时显示省略号、弹窗显示来回移动的不确定进度条，不伪造数值。
- 多文件时状态栏显示按**文件大小加权**的总进度，弹窗额外显示“第 2/3 个”；每个文件的百分比仍来自 ADB 自己上报的数值。
- 弹窗内同时显示进度条、已传输百分比和取消按钮；取消会终止本次传输。
- 推送成功后会回读手机端文件大小核对，不一致时提示“手机上的文件不完整”，不会把失败当成功。
- 推送成功后会要求手机媒体库重新扫描这些文件。通过 ADB 写入的文件属于 shell 用户、没有“下载”记录，不扫描时可能已经在 `/sdcard/Download/` 里，却不出现在手机“文件管理”的下载/最近/安装包等分类中。
- 推送成功后会把这些文件在手机上的修改时间设为推送时刻。手机“文件管理 → 下载”按文件时间排序分组，而 `adb push` 会保留本机文件的旧时间；不改时间的话，旧文件会被排到很下面，看起来像没传过去。代价是照片/视频在手机上显示的日期会变成推送时间。
- 手机剩余空间不足时推送会失败，失败原因来自 ADB（例如 `No space left on device`），先清理手机空间再试。
- 只接受普通文件，拒绝目录和符号链接；一次最多 50 个，选中文件重名时会要求先改名。
- 目标文件名取自本机文件名，手机已有同名文件会被覆盖。
- 推送目标由 ADB 当前已连接的手机决定：已记住的手机在线时优先使用它，否则要求当前只有一台手机在线。

辅助程序通过伪终端运行 `adb push`，把 ADB 实际输出的 `[ 37%]` 这类进度转成按行 JSON 事件交给插件，因此进度来自 ADB 本身，而不是按文件大小估算。较新的 ADB（例如 37.0.0）不再输出这种进度行，此时只能显示不确定进度条；文件是否送达以推送结束后的手机端大小核对为准。

## 从手机下载文件

弹窗右上角的文件夹图标切换到“手机文件”：

- 从 `/sdcard` 开始浏览，点文件夹进入、点“上级”返回，刷新按钮重新读取当前目录。
- 单击文件是选中，**双击**会弹出“下载到电脑？”确认，确认后下载到 `~/Downloads`；同名文件会改名为 `名称 (1).扩展名`，不会覆盖已有文件。
- 下载时弹窗顶部显示进度和取消按钮，状态栏的手机图标也会显示 `↓百分比`，和推送时的百分比一样；取消会删除未完成的本地文件。
- 结束后弹窗显示本机保存路径，并核对手机与本机文件大小一致。
- 只浏览和下载，不修改手机上的文件；目录一次最多显示 400 项，超出时进入子目录查看。

辅助程序用 `adb shell stat` 读取目录、用 `adb pull` 下载单个文件；下载进度来自对本机目标文件大小的轮询，不是按目录估算。无线调试偶尔会掉线，浏览或下载前如果发现手机不在 ADB 列表里，辅助程序会先用记住的地址自动重连一次。

启动 scrcpy 时的输出会写入 `${XDG_STATE_HOME:-~/.local/state}/dms-phone-connect/scrcpy.log`（每次连接覆盖）。直接在 scrcpy 窗口里拖放文件是 scrcpy 自带的功能，不走本插件；它失败时原因会出现在这个日志里。

拖放和推送的关键步骤会写到 DMS 日志，可用 `journalctl --user -u dms.service | grep phoneConnect` 查看是否真的收到了拖放。

纯 Go 辅助程序使用参数数组调用 `adb` 和 `scrcpy`，不调用 shell；配对码只通过标准输入传给 ADB，不保存。成功启动投屏后，在 `${XDG_STATE_HOME:-~/.local/state}/dms-phone-connect/device.json` 保存一个设备的 ADB 标识及可确认的 IP、连接端口和名称；扫描不可用时可以只保存 ADB 标识，界面不会继续显示旧地址。「忘记设备」会删除记录，并防止同一标识或 IP 的设备立刻被自动记回，直至你再次主动连接。关闭 DMS 不会关闭已启动的 scrcpy 窗口。

运行当前插件测试：

```bash
CGO_ENABLED=0 go test . -count=1
qmllint PhoneConnect.qml PhonePopout.qml PhoneOptions.qml PhoneSource.qml ComputerConnect.qml ComputerSource.qml
```
